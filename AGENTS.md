## 1. Видение проекта
Omnitask Local — это приватное приложение для управления задачами с принципом local-first для Windows и Android. Основная цель — создать легкую и безопасную альтернативу оригинальному Omnitask, исключив все облачные зависимости, слои MCP и многопользовательскую сложность.

Приложение следует «философии Obsidian»: пользователь владеет своими данными, сам указывает путь к хранилищу и самостоятельно настраивает синхронизацию.

## 2. Основные требования
Функционал и оформление за основу взять проект /home/agent/projects/mcp-todo

### 2.1 Функциональные требования
- **Выбор локальной базы данных:** При первом запуске пользователь выбирает локальную директорию, которая будет служить «хранилищем» (vault) для задач.
- **Управление задачами (CRUD):**
    - Создание, чтение, обновление и удаление задач.
    - Поддержка заголовков, описаний, дедлайнов и уровней приоритета.
    - Отметка задач как выполненных/невыполненных.
- **Постоянство данных:** Все данные должны храниться в одном файле (или небольшом наборе файлов) внутри выбранной директории.
- **Локальные уведомления:** Системные напоминания о задачах с дедлайнами (специфично для каждой платформы).
- **Кроссплатформенный UI:** Единый пользовательский опыт для Windows и Android.

### 2.2 Нефункциональные требования
- **Без Облака/API:** Полное отсутствие связи с внешними серверами, вебхуками или MCP-прокси.
- **Однопользовательский режим:** Отсутствие аутентификации и управления пользователями.
- **Приватность:** Данные никогда не покидают устройство пользователя, если они не перемещаются внешними инструментами синхронизации.
- **Низкие системные требования:** Минимальное потребление оперативной и процессорной памяти.

## 3. Техническая архитектура

### 3.1 Слой хранения данных
- **Основной выбор:** SQLite.
    - Высокая производительность запросов и фильтрации.
    - Атомарная запись для предотвращения повреждения данных.
    - Формат одного файла (`tasks.db`), который легко синхронизировать.
- **Альтернатива (в случае конфликтов SQLite):** JSON-файл на каждую задачу (в стиле Obsidian).
    - Более простое разрешение конфликтов через Syncthing.
    - Более низкая производительность при больших списках.

### 3.2 Стратегия синхронизации
- **Внешняя синхронизация:** Приложение не реализует собственный механизм синхронизации.
- **Рекомендуемый инструмент:** Syncthing.
    - Пользователь связывает папку «хранилища» на Windows и Android через Syncthing.
    - Приложение просто читает и записывает данные в синхронизируемую папку.

### 3.3 Технологический стек (предлагаемый)
- **Фреймворк:** Flutter (Dart).
    - Единая кодовая база для Windows и Android.
    - Отличная поддержка SQLite (`sqflite` / `drift`).
    - Производительность, близкая к нативной, на обеих платформах.
- **База данных:** `sqlite3` / `sqflite`.
- **Уведомления:** `flutter_local_notifications`.

## 4. Безопасность и шифрование
- **Шифрование БД:** Использование SQLCipher (AES-256) для прозрачного шифрования файла `tasks.db`.
- **Управление ключом:** Пароль пользователя преобразуется в ключ шифрования.
- **Варианты хранения ключа:**
    - Ввод пароля при каждом запуске (максимальная безопасность).
    - Сохранение в защищенном хранилище ОС (Android Keystore / Windows DPAPI) для прозрачной работы.
- **Важное предупреждение:** В local-first приложении нет облачного восстановления. Потеря пароля означает полную потерю данных. Это должно быть четко указано в интерфейсе.

## 5. Пользовательский интерфейс (UI)
- **Экран приветствия (Onboarding):** Простая кнопка «Выбрать папку хранилища».
- **Главный экран (Dashboard):** 
    - Список активных задач.
    - Фильтрация и сортировка по приоритету и дедлайну.
    - Кнопка быстрого добавления.
- **Просмотр задачи:** Полноэкранный редактор для описания задачи и метаданных.
- **Настройки:** Путь к текущему хранилищу, переключатели уведомлений.
